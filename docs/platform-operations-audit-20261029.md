## 선정 방식과 권한

- 생성/수정 configured 요청의 `campaign.selectionMode`: `BRAND_DIRECT` 또는 `OPERATOR`.
- 생성 기본값은 계약상 BRAND_DIRECT. 이전 수정 폼에 값이 없으면 필드를 생략하여 서버 현재값을 유지합니다. 미지원 enum은 전송하지 않습니다.
- 신청 이력이 있으면 서버가 방식 변경을 409로 거절하며 기존 편집기의 재조회 잠금을 유지합니다.
- 업체 명령은 기존 `/api/campaigns/applications/{id}/select|reject`; 명시 BRAND_DIRECT + SUBMITTED UI만 활성화합니다.
- 관리자 `/admin/campaign-participants`는 AdminAccess로 보호됩니다. GET `/api/admin/campaign-applications`, PATCH `/api/admin/campaign-applications/{id}/select|reject`만 사용합니다.
- 관리자 목록에는 서버가 OPERATOR만 반환하며 프론트도 명시 selectionMode를 다시 확인합니다. 브랜드 직접 선정에 운영자 재승인을 추가하지 않았습니다.
- 최종 소유권·정원·상태·운영자 권한은 서버가 검증합니다.

## API 및 데이터 보존

취소는 PATCH `/api/campaigns/applications/{id}/cancel`의 `{reason}`이며 주문·결제 취소와 다릅니다. 응답의 본인 신청 ID와 CANCELLED를 확인하고 최신 작업공간을 재조회합니다. 콘텐츠 제출 이후 상태에는 취소 버튼을 열지 않습니다.

알림의 `targetId`는 대상별 의미가 다릅니다. CAMPAIGN_APPLICATION은 applicationId, CAMPAIGN_CONTENT는 contentId로 이동합니다. 사용자 알림은 내 캠페인 목록, 업체 문의함 알림은 업체 참여자/콘텐츠 목록으로 연결합니다. URL 매개변수로 임의 권한을 부여하지 않으며 알림에서도 상세는 사용자가 목록에서 선택합니다.

브랜드 담당자 연락처와 신청자 배송 연락처는 별개입니다. 배송정보는 서버가 반환한 값만 표시하고 수락 전/미제공 상태를 구분합니다. 회원 전화번호를 자동 보완하지 않습니다.

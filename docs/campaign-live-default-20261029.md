# 캠페인 실제 조회 기본값과 예시 분리

## 변경

- 개발 환경에서도 기본값은 실제 공개 API 조회입니다. VITE_CAMPAIGN_DATA_MODE=preview를 명시한 개발 실행만 예시 목록을 사용합니다. 미설정·live·알 수 없는 값과 프로덕션은 실제 조회입니다.
- 예시 상세의 안내와 버튼을 '신청 폼 미리보기'로 명확히 표시했습니다. 실제 신청 전송 버튼은 계속 비활성화합니다.
- 예시 상세와 모달의 '실제 모집 중인 캠페인 보기'는 /category/제품?data=live로 이동합니다. 명시적 preview 실행에서도 이 링크는 실제 목록을 조회합니다. demo ID를 실제 캠페인 ID로 바꾸지 않습니다.
- 예시 목록은 실제 요청 상태에 저장하지 않습니다. 실제 빈 응답은 빈 목록, 오류는 오류 안내로 남기고 샘플로 대체하지 않습니다.
- 공개 DTO의 선택 필드 representativeImageUrl을 해당 카드에 그대로 연결합니다. 누락·null·빈 값은 이미지 준비 중, URL 로딩 실패는 이미지 오류를 표시합니다. 다른 상품이나 예시 사진으로 대체하지 않습니다.

## 이미지 계약과 실행 환경

백엔드 CollaborationDtos.CampaignResponse.from 및 docs/integration-product-campaign-catalog.md를 확인했습니다. GET /api/collaborations/campaigns/open의 각 항목에서 대표 이미지 URL을 반환합니다. 기존 필드 없는 응답도 지원합니다.

초기 시드의 /uploads/brands/... URL은 프론트에서 200 text/html로 응답하여 이미지가 아니었습니다. 백엔드가 캠페인에 직접 연결된 로컬 테스트 배너 5종으로 갱신했고 /assets/discovery/banners/*.png가 실제5174에서 모두 200 image/png로 응답했습니다. /uploads 프록시 추가나 임의 URL 치환은 필요하지 않아 하지 않았습니다. 이 이미지는 테스트 배너이며 실제 상품 촬영 사진이 아닙니다.

사용자5174 서버와 기존 /api→18080 연결은 유지했습니다. 기본모드/preview 검수만 별도5191/5192 서버에서 수행했습니다.

## 필터 범위

제품 카테고리 선택은 차단되어 있지 않으며 실제 category 값으로 정상 필터링됩니다. 채널·지역·종류·인기·선정확률의 미지원 값은 추측하지 않습니다. 현재 실모드 정렬 UI는 서버 제공 순서로 고정되어 있고 예시의 인기/선정확률 지표를 사용하지 않습니다. 지역·기자단 등 전체 메뉴 개편 및 새 서버 필터 계약은 이번 범위에 포함하지 않았습니다.

기존 사용자 QA 문서 변경과 미추적 자료는 수정하거나 커밋하지 않았습니다.

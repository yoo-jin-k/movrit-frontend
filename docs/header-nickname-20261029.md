# 공통 헤더와 회원 닉네임

## 화면 구성

- MainHomeHeader를 메인·탐색, CommonLayout, BuyerLayout 및 기존 AppHeader 호출부가 재사용합니다.
- 로그인, 회원가입, 비밀번호 찾기/재설정, 공지사항/상세, 활동 프로필, 고객센터, 알림, 마이페이지 및 구매자 화면의 헤더를 통일했습니다.
- 독립 활동 대시보드·협업·업체 신청과 인증 콜백에도 같은 헤더를 연결했습니다. 기존 본문 컴포넌트는 유지했습니다.
- 업체 BusinessShell과 운영자 AdminLayout은 별도 업무 레이아웃을 유지합니다.
- 헤더 글꼴과 기본 입력 스타일을 자체 범위에 지정하여 본문 스타일을 변경하지 않습니다.

## 회원 표시 및 권한

로그인 계정 버튼은 GET /api/auth/me의 nickname을 표시합니다. 조회 실패 또는 닉네임 누락 시 실명을 대신 표시하지 않고 '내 계정'으로 표시합니다. 프로필 저장 성공 시 서버 회원 정보를 다시 조회합니다. 라우트 이동 시 헤더 상태를 초기화하고 로그아웃 후 계정 메뉴를 제거합니다.

- 모든 로그인 사용자: 마이페이지 가기 → /mypage
- GET /api/sellers/me의 status가 APPROVED인 회원: 브랜드 관리 페이지 → /seller/dashboard
- GET /api/auth/me의 role이 ADMIN인 회원: 관리자 페이지 → /admin/dashboard
- USER와 업체 승인은 운영자 권한이 아닙니다. 관리자 직접 URL도 auth/me의 ADMIN 확인 후 렌더링합니다. 서버 API 인가는 별도로 유지됩니다.
- 드롭다운은 버튼 aria-expanded, Tab 이동, Escape 후 버튼 초점 복귀, 바깥 포인터 닫힘을 지원합니다. 긴 닉네임은 말줄임하고 320px 화면에서도 메뉴를 화면 안에 표시합니다.

## API 연결

백엔드 docs/member-nickname-api.md와 DTO/컨트롤러/서비스를 확인해 연결했습니다. 모든 응답은 JSON이며 페이지네이션은 없습니다.

| 작업 | 메서드 및 경로 | 요청/응답 |
|---|---|---|
| 가입 | POST /api/members/signup | email, password, name, nickname, phone → 201 회원 정보 |
| 본인 조회 | GET /api/members/me | Bearer 인증 → 200 id, email, name, nickname, phone, status |
| 닉네임 설정 | PUT /api/members/me | Bearer 인증, name/phone 보존 + nickname → 200 저장된 회원 정보 |
| 헤더 계정 | GET /api/auth/me | Bearer 인증 → 200 id, email, name, nickname, role(USER/ADMIN) |
| 업체 승인 확인 | GET /api/sellers/me | Bearer 인증 → 업체 status; 404는 업체 프로필 없음 |

신규 nickname은 필수입니다. 앞뒤·연속 공백을 정리하고 한글 완성형·영문·숫자·밑줄·공백 2~20자를 허용합니다. 서버와 DB가 중복 여부를 검증합니다. 400은 입력 오류, 409는 이메일/닉네임 충돌로 안내하고 입력을 보존합니다. 본인 설정에서는 nickname을 항상 전송하며 실명/연락처는 조회값을 보존합니다. phone은 null일 수 있습니다. 이메일·권한은 수정 요청에 포함하지 않습니다. 401은 기존 인증 갱신/로그인 처리를 따릅니다. 닉네임 없는 저장 응답은 성공으로 표시하지 않습니다.

기존 프로필 수정 화면의 고정 예시 데이터를 실제 회원 조회와 닉네임 저장 폼으로 교체했습니다. 채널 프로필 별칭과 회원 닉네임은 별개입니다.

## 검수 근거

- 1440/390/320px × 비로그인/로그인 대표 경로 45조합: 헤더 1개, 너비, 로고 위치, 높이, 로그인 표시, 전체 메뉴 Escape 확인
- 같은 화면 크기·로그인 조건에서 헤더 높이/로고 위치 동일
- 3개 화면 크기 × 비로그인/일반/승인 업체/대기 업체/운영자/조회 오류 18조합: 드롭다운 역할별 링크, 화면 경계, 긴 닉네임, Escape, Enter, 외부 클릭, 비운영자 직접 URL 차단
- 합성 API 프로필 검수: 공백 정규화, name/phone 보존, 저장 후 헤더 갱신, 새로고침, 409 입력 보존
- 위 브라우저 자동 검수의 계정 및 응답은 합성 값이며 서버 인증을 통과한 실제 계정 검수와 구분합니다.
- 증거: 프로젝트 deliverables/frontend-header-20261029의 JSON 결과와 PC/모바일 PNG

기존 QA 문서 수정, 미추적 복사본, experience와 기타 자료는 보존하고 이 작업 커밋에서 제외합니다. 채팅·쪽지, 운영 배포는 이번 범위에 포함하지 않습니다.

## 실제 로컬 서버 검수 완료

localhost:5174 → localhost:18080 연결에서 합성 응답 없이 확인했습니다.

- 기존 일반 사용자: 로그인, 닉네임 저장, 헤더 갱신, 새로고침, 로그아웃 시 메뉴 제거, 재로그인 후 값 유지. 검증 후 원래 닉네임 복구.
- 승인 브랜드: 브랜드 관리 링크 표시. 심사 대기 브랜드: 링크 미표시.
- 일반·승인 브랜드·심사 대기 브랜드의 관리자 직접 URL 차단. 일반·승인 브랜드의 실제 관리자 API는 403.
- 신규 가입 폼: 닉네임을 포함해 생성 후 로그인·새로고침에서도 표시 유지.
- 타 회원 닉네임으로 수정: 실제 409, 입력 보존, 새로고침 후 저장값 변경 없음.
- 신규 가입 UI 검수용 qa-header-* 계정 2개를 로컬 테스트 DB에 생성했습니다. 운영자 권한 부여와 실메일 전송은 하지 않았습니다. 비밀번호는 문서나 저장소에 기록하지 않습니다.
- 관리자 허용 메뉴/레이아웃은 합성 ADMIN 응답으로 검수했습니다. 실제 관리자 계정 로그인 및 외부 소셜 로그인 전체 흐름은 이번 프론트 검수에 포함하지 않았습니다.
- 최종 format:check, lint, build 통과. 기존 92개 + 닉네임 입력 2개 = 테스트 94개 통과.

실제 가입 직후 정상 복귀 위치가 /home인 기존 동작을 유지했습니다. 검사 스크립트는 /mypage 및 /home 두 정상 로그인 경로를 허용합니다.

# 계정 설정 프론트 검증 — 2026-10-29

## 구현

- 공통 닉네임 메뉴의 마이페이지·관리 페이지 아래 회색 구분선, 설정, 로그아웃을 추가했습니다.
- `/settings`는 로그인 후 사용하는 설정 허브입니다. 기존 `/mypage/profile` 닉네임 수정, `/settings/security` 비밀번호 변경, `/mypage/addresses` 실제 주소록으로 연결합니다.
- 비밀번호·주소록의 정적 예시와 비동작 버튼을 실제 API 연결로 교체했습니다. 닉네임은 기존 서버 저장·헤더 갱신 기능을 재사용합니다.
- 공통 로그아웃은 중복 요청을 막고 브라우저 토큰을 정리합니다. 서버 요청 실패 시 서버 로그아웃이 확인되지 않았다고 안내합니다. 로그아웃 이후 도착한 갱신 응답은 세션을 복구하지 않습니다.
- 비밀번호 기능은 보유 여부 조회, 현재 비밀번호 확인, 새 비밀번호 확인 일치, 영문·숫자/8~100자/UTF-8 72바이트 제약을 적용합니다. 서버 204 성공 후 현재 브라우저 세션을 종료하고 재로그인을 안내합니다. 모든 기기의 즉시 로그아웃을 주장하지 않습니다.
- `CURRENT_PASSWORD_MISMATCH`, `PASSWORD_REUSE`, `PASSWORD_NOT_CONFIGURED`, `PASSWORD_TOO_LONG_IN_BYTES`를 구분합니다. 비밀번호 변경 요청은 자동 인증 재전송하지 않습니다.
- 주소록의 조회·추가·수정·삭제 확인·기본 배송지 지정, 최대 10개, 첫 주소 기본 지정, 기본 주소 삭제 시 대체 안내를 제공합니다. 기존 캠페인 신청의 배송지 사본을 변경하지 않는다고 안내합니다.
- 조회 실패·빈 목록·저장 실패를 구분하며 결과 불확실 시 최신 조회 전까지 주소 재제출을 막습니다.

## 검증

- 전체 단위 테스트 110개, ESLint, Prettier, Vite 빌드 통과.
- 1440/390px 격리 브라우저: 메뉴 구분선/설정 링크/권한별 메뉴, 로그아웃 성공·실패/중복 요청 차단/토큰 삭제, 주소 CRUD, 비밀번호 불일치/현재 비밀번호 오류/성공 후 재로그인/소셜 전용 계정 표시 통과.
- 주소 조회 실패가 빈 목록으로 표시되지 않으며 쓰기 실패 후 잠금·재조회 복구·기본 배송지 변경 통과.
- 지연된 토큰 갱신 응답이 로그아웃 세션을 복구하지 않는 경합 검사 통과.
- 실제 FE 전용 합성계정: 1440/390px에서 주소 추가→수정→기본 지정→삭제와 현재 비밀번호 오입력 400/로그인 유지 통과. 검수 주소를 삭제하고 기존 기본 주소를 복원했으며 기존 주소 수와 동일함을 확인했습니다.
- 비밀번호 성공 변경은 격리 UI의 204 응답/세션 정리로 검증했고 실제 성공 변경은 별도 계정의 QA 담당 검수 범위입니다. 사용자 본인 비밀번호·주소와 신청 36/캠페인 30은 변경하지 않았습니다.

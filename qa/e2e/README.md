# 화면 전체 흐름 자동 점검 (Playwright)

통합 환경(백엔드 18080, 프론트 5174)이 켜져 있을 때 실제 화면을 조작해 주요 흐름을 점검합니다.
점검용 계정(`demo-*@movrit.local`)과 점검용 캠페인만 만들고 바꾸며, 실제 사용자 데이터는 건드리지 않습니다.

## 준비

```bash
nvm use                                  # Node 24
export MOVRIT_QA_PASSWORD='점검 계정 비밀번호'   # 저장소에 적지 않습니다
cd qa/e2e && mkdir -p e2e shots
```

Playwright는 설치된 Chrome(`channel: 'chrome'`)을 사용합니다.

## 스크립트

| 순서 | 파일                             | 하는 일                                                                                                                                                             |
| ---- | -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1    | `e2e-brand-create.mjs`           | 업체가 작성 화면에서 캠페인 등록(`RECRUIT=1`로 모집 인원 지정)                                                                                                      |
| 2    | `e2e-apply.mjs`                  | 사용자가 상세 화면에서 신청(`EMAIL`, `APP_FILE`로 계정·저장 파일 지정)                                                                                              |
| 3    | `e2e-flow.mjs`                   | 업체 선정 → 참여 수락 → 체험 확인 → 콘텐츠 제출 → 업체 검토 → 운영자 최종 승인                                                                                      |
| —    | `e2e-admin-approve.mjs`          | 운영자 '콘텐츠 최종 승인' 화면에서 승인                                                                                                                             |
| —    | `qa-checks.mjs`                  | 정원 경합(동시 선정), 다른 브랜드 권한, 배송 정보 중복, 신청 스냅샷 보존                                                                                            |
| —    | `route-check.mjs`                | 비회원·사용자·업체·운영자로 62개 경로를 열어 오류·빈 화면 확인                                                                                                      |
| —    | `admin-check.mjs`                | 관리자 화면 14개 실제 데이터 표시, 공지 작성→사용자 표시, 회원 정지·해제                                                                                            |
| —    | `ops-extras-check.mjs`           | 커뮤니티 운영자 가리기, 리포트 기간·엑셀, 콘텐츠 성과, 캠페인 서버 검색                                                                                             |
| —    | `access-control-check.mjs`       | 남의 자료 접근 점검(참여자↔참여자, 업체↔업체, 일반 회원→운영자 API, 배송지·알림·글, 비공개 업로드 폴더). 준비: qa-checks.mjs로 demo-brand2 계정                   |
| —    | `participation-change-check.mjs` | 신청 철회·참여 취소(단순·협의+증빙)·기간 연장(직접 연장·연장 횟수 기준 포함)·미제출 자동 취소·업체 미선정·방문형 선착순·내 캠페인 달력. 점검 계정에 생긴 취소·연장 누적 패널티는 끝에서 취소합니다 |
| —    | `channel-bio-code-check.mjs` | SNS 소개글 인증 코드: 코드 발급, 실제 네이버 블로그 RSS로 '코드 없음'·'없는 블로그' 확인, 인스타그램 운영자 확인 넘김 → 운영자 화면 코드 표시 → 승인. demo-user를 쓰고 끝에 연결을 해제합니다(인스타그램 흐름은 코드 발급 제한으로 하루 5번까지) |
| —    | `phone-verification-check.mjs` | 휴대폰 인증(시연 방식): 번호 형식, 시연 인증번호 표시, 틀린 번호 차단, 인증됨 표시, 다른 회원 같은 번호 409, 운영자 회원 상세. demo-user를 쓰고 끝에 연락처를 되돌립니다(회원당 1시간 5번 제한으로 한 시간에 두 번 정도까지) |

# 이메일 임시 정책 및 실제 신청 프론트 인계

## 현재 상태

백엔드 기준은 `b5a273611164245c34732b052ad882966372949e`입니다. 기존 정책 승인 검토 차단 안내는 과거 상태이며, 최신 서버 계약에 맞춰 실제 신청 폼 연결을 완료했습니다. 이메일 소유 확인과 실명 본인인증은 별도로 표시합니다.

- GET `/api/campaigns/{id}/eligibility`의 canApply, blockingReasons, alreadyApplied, formVersion을 확인합니다.
- 서버 허용, 이메일 확인, 채널 등록, 중복 없음, 차단 없음, 표시 중인 폼 버전 일치일 때만 실제 신청 폼을 표시합니다.
- 신청은 POST `/api/campaigns/{id}/applications`의201과 신청id 확인 후 접수 안내를 표시합니다. 조건충돌409는 재입력 전에 최신조건을 다시 조회하도록 합니다.
- 이메일 상태/요청/확인은 기존 인증 클라이언트를 사용합니다. 계정의 현재 이메일만 표시하며 임의 주소 변경 기능을 만들지 않았습니다.
- 인증번호 재발송·만료·필드 오류·429제한·503미설정·통신 실패를 구분합니다. 요청 제한시간은15초입니다.
- 로그인 후 요청했던 캠페인 상세로 복귀합니다. 개인정보·인증번호는 저장소나 로그에 남기지 않습니다.

## QA 범위

최신 파일 버전은 `frontend-release-version.sha256`입니다. 이전 QA007 및 이메일 준비본 결과가 새 버전에 자동 적용되지는 않습니다. 로그인 상태에서의 브라우저 인증·신청 흐름, 실제 메일 만료/재사용/재발송, 신청201은 QA의 격리 실행 증거와 구분해 기록합니다.03은 캠페인10 신청을 생성하지 않았으며 QA와 한 번만 생성하도록 조율했습니다.

## QA13 로그인 오류 안내 보완

검수 진입 주소는 `http://localhost:5174`로 사용합니다.403은 접속주소/접근권한 차단,401은자격증명오류,429는요청제한,5xx는서버오류,무응답은연결실패로구분해화면에안내합니다.비밀번호가포함될수있는Axios오류객체콘솔출력은제거했습니다.추가2테스트·ESLint·빌드통과. 빈POST를프록시로재확인했을때localhost와127.0.0.1 Origin모두400으로현재403은재현되지않았습니다. 백엔드CORS정책은수정하지않았습니다.

# 프로필 사진·계정 카드 프론트 검증 — 2026-10-29

## 구현

- 닉네임 메뉴를 약 450px 계정 카드로 구성했습니다. 64px 원형 사진과 카메라 링크, 채널 네 칸, 캠페인 요약/빈 상태, 포인트 준비 중, 관심 목록·등록 콘텐츠 순서입니다. MOVRIT 색상과 로고를 유지하고 자체 SVG 아이콘을 사용했습니다.
- 하단 구분선 뒤 마이페이지·설정·로그아웃·권한별 브랜드/관리자 이동을 유지합니다. 모바일은 화면 너비에 맞춰 줄고 카드 내부를 스크롤할 수 있습니다. Escape는 닫은 뒤 실행 버튼으로 초점을 돌립니다.
- 카메라 → `/settings#profile-photo` → 사진 선택 → 저장 전 미리보기 → 사진 저장 경로입니다. 파일 선택은 label 안의 키보드 접근 가능한 input과 포커스 표시를 사용하고 선택 파일명을 표시합니다.
- `PUT /api/members/me/avatar`의 multipart `file`과 `DELETE /api/members/me/avatar`를 사용합니다. JPEG/PNG·5MiB를 사전 검사하고 실제 형식·이미지 크기·재인코딩은 서버 검증에 따릅니다. 업로드 응답의 `avatarUrl`, 삭제 204를 확인한 뒤 공통 회원 갱신 이벤트를 보냅니다.
- 헤더·마이페이지·내 정보·설정은 서버의 버전 사진 URL을 사용합니다. 이미지 조회 실패 시 기본 아바타로 돌아갑니다. 임시 미리보기 URL은 선택 변경과 화면 이탈 시 해제합니다.
- 저장 실패 때 성공으로 표시하지 않으며 서버 사진 재조회가 성공한 뒤 재시도를 허용합니다.
- `/settings`는 프로필 사진·기본 정보·로그인 및 배송 정보 그룹으로 구분하고 기존 닉네임/비밀번호/주소 기능을 재사용합니다.
- 채널 상태는 실제 channel-profile 지표 등록 여부이며 OAuth 연결 상태라고 표시하지 않습니다. 캠페인은 본인 신청 목록에서 집계합니다. 실패를 0건으로 바꾸지 않습니다.
- 관심 목록은 기존 프론트 함수가 있지만 실제 백엔드 계약/구현이 없어 준비 중으로 표시합니다. 새 찜 API나 금전 기능을 만들거나 0건·0포인트로 표시하지 않았습니다. 기존 즐겨찾기 페이지는 변경하지 않았습니다.
- `/mypage/contents`는 기존 본인 제출 콘텐츠 API의 실제 목록이며 기존 캠페인 제출·검토 경로로 연결합니다.

## 검증

- 단위 테스트 112개, ESLint, Prettier, Vite 빌드 통과. 빌드에는 메인 번들 500KB 초과 권고가 남아 있습니다.
- 격리 UI 1440/390px: 카드 구성, 카메라 이동, 미리보기만으로 쓰기 없음, multipart 저장 1회, 헤더/마이페이지/내 정보 동기화, 삭제, SVG 사전 거부, 서버 오류 잠금, 활동 오류와 0건 구분, Escape 초점 복귀, 가로 넘침 없음 통과.
- 키보드 파일 입력 초점 표시, 신청·선정·진행·완료 요약 집계와 등록 콘텐츠의 게시물/캠페인 작업 링크 검증 통과.
- 실제 FE 전용 합성 계정: 1440/390px에서 자체 생성 PNG 저장 → 공개 사진 200 → 세 화면 동기화 → 삭제 → 이전 URL 404 통과. 검수 후 avatarUrl=null 상태로 복원했습니다.
- 실제 검수 첫 로그인에서 서버 교체 구간의 502를 만나 쓰기 없이 중단한 뒤 정상 응답 복구 후 재개했습니다.
- 사용자 본인의 사진과 외부 서비스의 개인 사진·닉네임·이미지 자산은 복사하거나 변경하지 않았습니다.
